# Rulebook: Structuring Reports

Rules for writing reports that get read and acted on. Read this document to learn the craft; give it to a model to apply it. It governs any report whose reader must decide or act on it: the twelve types named in section 2. The document under work is called the report. Write the report against these rules, then audit it against them one at a time. The rules are staged, not simultaneous, so the rulebook's size does not collide with the constraint budget it prescribes.

![The Strategist](images/reports-rulebook.png)

## 1. Protocol

Execute these steps in order when given a report:

1. Read the whole report and name its type from section 2 before changing anything; when no report exists yet, name the type and write a draft first.
2. Audit it against section 3 (every report), then against the one section-4 block that matches its type.
3. Rewrite each violation in place; preserve the report's evidence, findings, and voice, and change how it reads, not what it claims.
4. Verify every name, number, date, quotation, and citation against a source; where a fact resists verification, flag it and leave it unchanged rather than smoothing it into certainty.
5. Run the section 6 checklist on the revision and fix what fails.

## 2. Report types and goals

Name the type before writing; it sets the skeleton and the epistemic stance. Every type is answer-first (rule 3.1), and every report longer than two pages fills one default scaffold: front matter (title, executive summary, contents), body (introduction, background, method, findings, discussion, conclusions and recommendations), and back matter (references, appendices). Section 4 says how each type reshapes that body; a short or informal report collapses the scaffold to a memo but keeps the order.

1. Informational / status - record facts or current state without interpreting them. Shape: summary, facts by time, task, or topic, brief status close.
2. Analytical / recommendation - analyze a problem against criteria and recommend an action. Shape: answer, criteria, options, recommendation. Subsumes feasibility, consulting, and market-research reports.
3. Research / scientific - report an inquiry so a peer can evaluate and reproduce it. Shape: abstract, then IMRaD (introduction, methods, results, discussion).
4. Assurance / audit / compliance - give an independent opinion on whether something conforms to a standard. Shape: opinion first, basis for the opinion, responsibilities.
5. Due-diligence / risk - rate the risks in a target before a transaction or decision. Shape: go / no-go call, risk register, topical findings, recommended protections.
6. Intelligence / estimative - forecast or judge an uncertain situation for a decision-maker. Shape: key judgments, evidence, assumptions, alternatives.
7. Incident / postmortem - explain a failure and prevent its recurrence, blamelessly. Shape: impact, timeline, root cause, owned action items.
8. Investigative / fact-finding - establish contested facts about conduct and reach defensible findings. Shape: allegations, process, evidence, findings per allegation.
9. Evaluation / review - judge how well an artifact, design, or program meets criteria and prescribe fixes. Shape: summary, method, severity-ranked findings, recommendations. Covers peer review, code and design review, usability studies, and creative critique.
10. Legal / advisory memorandum - predict how a rule applies to facts and advise. Shape: question presented, brief answer, facts, discussion, conclusion.
11. Policy brief / white paper - move a decision-maker toward an action or position. Shape: problem, options with trade-offs, recommendation as a call to action.
12. Subject profile / dossier - profile a person, entity, or system from the record. Shape: identity and context, evidence organized by trait or criterion, synthesis or classification.

Regulated and domain variants (financial 10-K, clinical CARE case report, environmental impact statement) borrow a type's shape under a fixed template; follow the template, then apply that type's block. When the type is unclear, classify on four axes: informational or analytical (does it record or judge), formal or informal (length and apparatus), internal or external (who reads it), periodic or one-off (does it recur). The axes set apparatus and tone; the type sets the skeleton.

## 3. Rules for every report

These hold for every type. Apply each as its own pass.

### 3.1 Structure and ordering

- Lead with the answer; put the conclusion, recommendation, or key judgment in the first paragraph, because most readers stop early. (Minto; NN/g)
- Give any report over two pages a stand-alone executive summary a decision-maker can act on without the body, because many read only the summary. (USC; Harvard Kennedy School)
- Order the body by importance, not by the order the work was done, because the reader needs conclusions before process. (Federal Plain Language Guidelines)
- Group supporting points so they are mutually exclusive and collectively exhaustive, because overlap and gaps both cost the reader trust. (Minto)
- Layer detail: essentials in the body, depth in appendices, so cutting from the bottom never removes the core. (NN/g)

### 3.2 Headings and navigation

- Write headings that state the point, not the topic, so a reader scanning only the headings reconstructs the argument. (Minto; GOV.UK)
- Front-load the information-carrying word in every heading, because scanners read the first two words and skip the rest. (NN/g)
- Hold one grammatical form within a heading level and cap depth at about three levels, because parallelism and shallow hierarchy speed navigation. (Purdue OWL; NARA)
- Add a table of contents to any report over about ten pages, because a long document needs jump-navigation. (Federal Plain Language Guidelines)

### 3.3 Language and readability

- Write in the active voice and name the actor, because the passive hides who did what. (Federal Plain Language Guidelines; US Army AR 25-50)
- Prefer short, common words and cut every word whose removal changes nothing, because clutter slows every reader. (Zinsser)
- Keep sentences near 15-25 words and split anything longer at its joints, because long sentences raise the error rate. (GOV.UK; AR 25-50)
- Use one term per concept and define each specialist term once, because a synonym reads as a new thing. (Federal Plain Language Guidelines)
- Do not treat a readability score as a target; test with a real reader instead, because the formulas measure length, not clarity. (Redish and Selzer)

### 3.4 Paragraphs and flow

- Open each paragraph with its topic sentence and hold it to one idea, because scanners judge a paragraph by its first line. (Federal Plain Language Guidelines; NN/g)
- Begin sentences with familiar information and end with the new, because old-to-new flow lets the reader connect them. (Williams)
- Use a run-in bold lead-in to open a long prose run, sparingly, because it front-loads the point without fragmenting the argument. (NN/g)
- Connect consecutive ideas with an explicit transition where the link is not obvious, because the writer sees a link the reader cannot. (Federal Plain Language Guidelines)

### 3.5 Evidence, sourcing, and honesty

- Cite every load-bearing claim and characterize the quality of its source, because a judgment is only as good as its sourcing. (ICD 203)
- State the evidence before the value word it supports; never write "significant" or "dominant" before the number that earns it. (IMRaD)
- Quantify with units and a comparison, because "$2.5M of revenue at risk" is harder to dispute than "significant risk". (Tufte)
- Separate what you observed from what you assume from what you judge, because blurring them lets a weak link pass as fact. (ICD 203)
- Disclose the limitations and assumptions the conclusion rests on, because a stated limit builds trust and a discovered one destroys it. (IMRaD)
- Never fabricate a fact, source, or quotation; where evidence is missing, say so and stop. (integrity norm; ICD 203)

### 3.6 Uncertainty and alternatives

- Express likelihood with a fixed ladder of terms (for example very unlikely, roughly even chance, likely, almost certain), because a shared vocabulary stops the reader reading different odds into the same word. (ICD 203)
- State likelihood and confidence separately and never combine them in one sentence, because one is about the event and the other about your evidence. (ICD 203)
- Present the credible alternatives and say why you set them aside, because a judgment that survived challenge earns more trust. (ICD 203)
- Weight positions by the evidence and refuse false balance, because equal air for unequal evidence manufactures a fake controversy. (weight-of-evidence reporting)

### 3.7 Visuals and format discipline

- Match the form to the content: prose for reasoning, a list for parallel items, a table for multi-variable comparison, a figure for a trend. (Federal Plain Language Guidelines)
- Do not bulletize an argument; keep reasoning and contested judgment in prose, because bullets strip the connectives the argument needs. (Tufte)
- Put data of two or fewer rows in a sentence, not a table, because a tiny table wastes the reader's attention. (Purdue OWL / APA)
- Maximize data-ink and cut chartjunk, and keep the size of the effect shown equal to the size in the data, because decoration and distortion both mislead. (Tufte)
- Caption every table and figure to stand alone, number them, and reference each before it appears, because a skimming reader uses them out of order. (Purdue OWL / APA)

WRONG (an argument dissolved into bullets that drop the causal link):

```
- Finance interests dominate governance.
- They chair three of five key groups.
- Their proposals pass at a higher rate.
```

RIGHT (the same evidence carried by prose that states the link):

```
Finance interests hold disproportionate governance power: they chair three of the five key working groups, and their proposals are adopted above the committee's average rate.
```

### 3.8 Revision and QA

- Draft the substance first and polish wording last, because sentence-level finish is wasted on paragraphs that will be cut. (Zinsser; Williams)
- Cut the first draft hard; expect to cut roughly half without losing content, because clutter is unfinished thinking. (Zinsser)
- Hold one tense, person, and stance throughout, because a shift disorients the reader. (Zinsser)
- Re-derive the summary and headings from the finished body, because the surface must sell the report that exists, not the one that was planned. (how-to-write-papers.md)
- Run the section 6 checklist and fix what fails, because a fixed checklist makes quality repeatable.

## 4. Per-type rules

Apply only the block that matches the report's type (section 2). Each block holds the rules that do not apply to every type; the section 3 rules still apply in full. Each block ends with the failure mode that most often sinks that type.

### 4.1 Informational / status

- Report facts and state only; move any interpretation or recommendation to an analytical report, because mixing them lets opinion ride as fact.
- Organize by a stable frame (time, task, or topic) and keep it across editions, because a periodic report is read by comparison.
- State done, in progress, next, and blocking explicitly, and say "nothing blocking" when true, because silence reads as an omission.
- Failure mode: interpretation smuggled into a record, or a status with no clear account of what is blocked.

### 4.2 Analytical / recommendation

- State the recommendation first, then the criteria it was judged against, then the options, because the reader weighs options against criteria, not in a vacuum.
- Give each option its trade-offs and name the do-nothing option, because a recommendation with no alternative is an assertion.
- Tie every recommendation to an owner and a next step, because an unactionable recommendation is a comment.
- For a feasibility variant, score the standard dimensions (technical, economic, legal, operational, scheduling) and end on go, modify, or abandon; for a consulting variant, build the pyramid from one governing thought.
- Failure mode: options with no criteria, or a recommendation the evidence above it does not support.

### 4.3 Research / scientific

- Follow IMRaD and keep results and their interpretation in separate sections, because evidence read before spin can be judged on its own.
- State the finding in the abstract, because the abstract is where a research report satisfies answer-first (rule 3.1) while the body still defers detail to the discussion.
- Give the method in enough detail to reproduce, because an unreproducible result is an anecdote.
- State the hypothesis or question up front and answer exactly it in the discussion, because a drifting question hides a null result.
- Failure mode: interpretation mixed into results, or a method too thin to repeat.

### 4.4 Assurance / audit / compliance

- State the opinion first (unqualified, qualified, adverse, or disclaimer), then the basis for it, because the reader wants the verdict before the workings. (ISA 700)
- Name the standard tested against and the scope examined, because an opinion with no criterion is unfalsifiable.
- Separate management's responsibility from the auditor's, because independence is the value being sold.
- Failure mode: a buried or hedged opinion, or findings with no stated criterion.

### 4.5 Due-diligence / risk

- Lead with a go, no-go, or conditional call, because the reader is deciding, not browsing.
- Rate each finding red, amber, or green, and let a single red core item veto a high aggregate, because one dealbreaker outranks many minor items. (OECD)
- Map each material risk to a protection (condition, indemnity, price adjustment), because a risk with no remedy is just worry.
- Failure mode: an undifferentiated list where the dealbreaker hides among the trivia.

### 4.6 Intelligence / estimative

- Open with Key Judgments, the bottom-line forecast stated before the evidence. (ICD 203)
- Tag each judgment with a likelihood term and, separately, a confidence level in the evidence. (ICD 203)
- Give the alternatives considered and the indicators that would change the judgment, because a forecast the reader cannot track is inert.
- For a reception or audience-impact forecast, model each audience segment and state what it does next, not only how it feels.
- Failure mode: a confident forecast with no likelihood tag, no alternatives, and no sourcing.

### 4.7 Incident / postmortem

- Write the timeline in UTC, facts only, before the analysis, because a sequence reconstructed after the fact bends to the conclusion. (Google SRE)
- Keep it blameless: name systems, actions, and gaps, not individuals, because blame suppresses the disclosure that prevents recurrence. (Google SRE)
- Quantify impact (duration, users, scope) in the summary, because severity sets the priority.
- Give every action item an owner, a due date, and a status, because an unowned fix does not happen.
- Failure mode: a narrative that assigns fault, omits UTC times, or ends without owned actions.

### 4.8 Investigative / fact-finding

- State the standard of proof (usually the balance of probabilities) and reach a finding on each allegation against it, because a finding with no standard is an opinion.
- Summarize each side's evidence neutrally before the finding, because a report that argues one side reads as partial.
- Keep the investigator's conclusions the investigator's own, uninfluenced by the commissioning party. (Burges Salmon)
- Failure mode: findings with no standard of proof, or evidence summarized to fit a conclusion.

### 4.9 Evaluation / review

- Judge against stated criteria and rank each finding by severity, because an unranked list gives the reader no order to act in.
- Back every finding with evidence (a quote, a location, a metric) and pair it with a fix, because a finding with no evidence is taste and one with no fix is a complaint.
- For an adversarial or red-team review, challenge every objection internally before it stands and seal the report with one verdict, because an untested objection is noise and a verdict makes the review actionable.
- Failure mode: severity-blind findings, or criticism with no evidence and no remedy.

### 4.10 Legal / advisory memorandum

- Open with the question presented and a brief answer, because the reader wants the prediction before the analysis.
- Work each issue as issue, rule, application, conclusion, and address the strongest counterargument, because a one-sided memo misleads the client who relies on it.
- Stay predictive, not persuasive, because the client needs the likely outcome, not advocacy.
- Failure mode: advocacy in place of prediction, or a conclusion that ignores the counterargument.

### 4.11 Policy brief / white paper

- Lead with the ask and keep every section serving it, because a brief is an instrument of persuasion, not a survey.
- Give options with trade-offs and one recommended action, because a decision-maker chooses among options.
- Size the brief to the reader's budget (one to eight pages) and write it in plain language, because an unread brief changes nothing.
- Failure mode: a literature review with no ask, or a recommendation with no feasible next step.

### 4.12 Subject profile / dossier

- Organize evidence by trait or criterion, not chronologically, because the reader wants a standing picture, not a timeline.
- Source every claim to the record and distinguish fact from inference, because a profile of a person carries the highest cost when wrong.
- State the classification or verdict the profile supports and the evidence gaps in it, because an unbounded profile invites over-reading.
- Apply clinical, diagnostic, or psychological framing to a named real person only with explicit sourcing and stated limits, and prefer describing behavior over labeling the person, because that framing on someone who is not your patient is the highest-risk move in the genre.
- Failure mode: chronology in place of synthesis, unsourced characterization, or a clinical label on a named person with no basis.

## 5. Prompting a model to write or audit a report

Apply this section when a model, not a person, drafts or audits the report. For the form of the instruction itself, and for any tool or subagent mechanics, follow [how-to-write-prompts.md](how-to-write-prompts.md); the rules here are the report-specific additions.

- Open the drafting prompt with a report brief: the model's role, the audience, the decision the report serves, the inputs and their locations, the constraints (length, what to exclude), and the output format, because the decision-served slot is what turns a summary into a report.
- Outline first and expand section by section against that fixed outline for any report over about two pages, then run one whole-document consistency pass; forbid one-shot drafting, because one-shot long output drifts and loses structure.
- Ground before prose: instruct the model to extract the relevant source quotes first, then write only from them, because quote-then-write cuts drift and fabrication. (Anthropic)
- Require cite-or-omit: every factual claim carries a source or is cut, and where evidence is missing the model writes "not in the sources" rather than inventing it.
- Require calibration: uncertainty expressed in-line, likelihood separated from confidence, alternatives surfaced, and a confidence tag on each key judgment, because models are overconfident by default.
- Strip generic filler by supplying context, not adjectives: give the audience, its prior knowledge, and the exact decision, and require a real number or quote in each finding.
- Close with a self-audit: draft, then check the draft against the section 6 checklist one rule at a time, then revise, because a report the model has not audited against named criteria keeps its first-draft defects.
- For subagent, tool, and large-assembly mechanics (dispatch a fixed block by tag reference, ship task text verbatim, trace every promised section into existence, concatenate large outputs through the shell), follow how-to-write-prompts.md section 8; do not re-derive them here.

## 6. Checklist

Run these on the finished report. Each answers yes or no; each no returns to its section.

- The type is named, and the answer, recommendation, or key judgment leads the document. (2, 3.1)
- A report over two pages carries a stand-alone executive summary. (3.1)
- Headings state points and reconstruct the argument when read alone. (3.2)
- Sentences run near 15-25 words, the voice is active, and one term names each concept. (3.3)
- Every paragraph opens on its topic sentence and holds one idea. (3.4)
- Every load-bearing claim is cited, evidence precedes its value word, and no fact is fabricated. (3.5)
- Likelihood and confidence are stated separately, and credible alternatives are addressed. (3.6)
- No argument is bulletized, and every table and figure has a stand-alone caption and a prior reference. (3.7)
- The summary and headings were re-derived from the finished body. (3.8)
- The per-type block for this type is satisfied end to end, including its failure mode. (4)
- If a model drafted it, the report brief, grounding, calibration, and self-audit were applied. (5)
- Every name, number, date, quote, and citation is verified or flagged. (1)
