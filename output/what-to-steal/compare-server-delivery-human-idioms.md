# Server-Delivered UI in Rust: What the Field Does and What to Steal

Report type: evaluation / review. It judges the promptforge-ws-server crate (the axum server that delivers the workshop UI) against six popular Rust codebases that use the same technique - a Rust HTTP server serving its own embedded web UI - and prescribes structures to adopt, in payoff order. It is the server-side companion to compare-ui-stack-human-idioms.md, which covered the frontend and shell.

## Executive summary

The verdict: our server's spawn contract, typed AppState, oneshot shutdown, and config interpolation already match or beat most of the field, including two codebases twenty times our size. Our real deficits are the ones we knew about - the duplicated WebSocket session scaffolding and the flat 30-50KB modules - and the field supplies precise, proven cures for both. A second theme emerged unprompted: the two heavily AI-authored codebases in the sample (Windmill at 80 percent, Spacedrive at 42 percent AI co-authored commits) are exactly the ones where duplication metastasized and god files survived crate splits, while the two single-author human codebases (Rustpad, Trailbase) are the cleanest. The lesson from the UI report repeats: structure survives only where guardrails are enforced, and AI authorship raises the required guardrail strength.

### Key findings

1. **The cleanest WebSocket session factoring eliminates our scaffolding rather than abstracting it.** Rustpad runs one task per connection with no outbox channel, no writer task, and no session registry: a `select!` over a `Notify` (durable log with a per-client revision cursor), a small broadcast channel (ephemeral, disconnect-on-lag), and the socket itself. Confidence: high.
2. **Session cleanup should be RAII, not manual.** Trailbase wraps every subscription stream in a Drop guard that deregisters on disconnect; Rustpad cascades teardown from a Drop impl on the document entry; OpenObserve cancels backend work from a Drop guard moved into the response stream. Nobody disciplined cleans up by hand. Confidence: high.
3. **The router decomposition norm is one `routes(state) -> Router` constructor per feature module, composed by nest/merge in a thin composition root, with per-route narrowed state.** Tabby, Windmill, and Trailbase all converge on it independently. This is the cure for our `app.rs`. Confidence: high.
4. **For the gateway merge, gate the leaf function, not the call site.** Windmill's `static_frontend` feature compiles the embed handler body conditionally while the router registration stays feature-blind, so one binary runs headless or UI-serving with an identical route tree. Trailbase shows the embeddable-server API shape and its footguns. Confidence: high.
5. **Held WebSockets block graceful shutdown forever; two independent codebases added a force-exit watchdog for exactly this.** We have the same exposure and should add the same roughly 40-line fix. Confidence: high.
6. **Split wire errors from init errors.** Trailbase keeps the wire error opaque, close to HTTP codes, with explicit conversions only, and lets the init error be rich and convenient - the right two-error shape for breaking up our monolithic error handling. Confidence: high.

## Method

We characterized our server first: axum with rust-embed assets (disk in debug, embed in release), two hand-rolled WebSocket endpoints (chat relay and voice) that duplicate session scaffolding, an `AppState` of seven services, in-process spawn on a dedicated thread with a oneshot shutdown, and TOML config with `${ENV_VAR}` interpolation. A search subagent then surveyed twenty candidate Rust projects that serve their own web UI, verifying each against its actual source, and shortlisted six for depth and diversity. Six parallel subagents shallow-cloned the repositories, verified authorship through the GitHub commits API (last 100 commits scanned for AI co-author trailers and generation markers), and analyzed the server code with file-and-line citations. Rustpad's core was additionally read first-hand in full.

## Baseline: where we already stand

Four of our existing choices are validated outright by this study. Our spawn contract (bind first, report the URL through a channel, then serve) is exactly Windmill's `run_server` signature and their test fixture depends on it. Our oneshot graceful shutdown beats Tabby, which has none at all. Our typed `AppState` beats OpenObserve, which injects nothing and reads global statics everywhere, making two in-process instances impossible - directly relevant since we plan to embed in the gateway. Our `${ENV_VAR}` TOML interpolation is simpler and stricter than Tabby's silently-defaulting loader and Trailbase's reflection-based protobuf merging, whose own FIXME admits env vars can silently fail to apply. The deficits are the known ones: `chat_ws.rs` (46KB) and `voice.rs` (49KB) duplicate session scaffolding and mix wire types, session lifecycle, and business logic; `app.rs` holds router, state, and errors in one file.

## Detailed findings, ranked by payoff

### Finding 1: the Rustpad session model - subtraction, not abstraction

We assumed the fix for our duplicated WS scaffolding was extracting the shared outbox-channel-plus-writer-task machinery into one abstraction. Rustpad, the cleanest known small WS server (read first-hand, `rustpad-server/src/rustpad.rs`, 340 lines total), shows that the machinery itself is unnecessary. Its model:

- **No outbox channel, no writer task, no session registry.** Each connection is exactly one task running a `select!` loop that owns the socket for both reading and writing (`handle_connection`, rustpad.rs:180-214).
- **Two outbound semantics, deliberately different.** Durable data (the operation log) is never pushed; a `Notify` wakes the loop, which compares the shared revision counter against its own per-client cursor and sends the missing slice (rustpad.rs:189-195, 250-266). Missing a wakeup is harmless because the next wakeup delivers everything since the cursor. Ephemeral data (cursors, presence, language) goes through a `broadcast::channel(16)`; a client too slow to keep up gets a `RecvError` and its connection drops, which is correct because ephemeral state is fully resent on reconnect (`send_initial`, rustpad.rs:216-248).
- **Lost-wakeup avoidance is documented in place**: request the notification first, then check state, the same order `tokio::sync::watch` uses (rustpad.rs:186-188).
- **Teardown cascades from Drop.** The expiry sweeper removes the map entry; the entry's `Drop` calls `kill()`, which flips an `AtomicBool` and `notify_waiters()`, and every connection loop observes the flag and exits (lib.rs:41-45, rustpad.rs:170-173, 189-192). Per-connection cleanup is three lines after the loop returns (rustpad.rs:141-145).
- **Shared state is one `parking_lot::RwLock<State>`** with an upgradable read for the validate-then-commit edit path (rustpad.rs:311-338).

Application to us: our chat relay's transcript-so-far is Rustpad's durable log (Notify plus cursor); our status bus and transcription interims are the ephemeral broadcast. The refactor deletes the duplicated outbox/writer scaffolding from both `chat_ws.rs` and `voice.rs` rather than moving it somewhere shared. What stays per-feature is only the protocol handler (the match on inbound messages) and the wire types. Confidence: high; this is the pattern's reference implementation and it maps onto both of our sockets.

Two complements from larger codebases. Tabby's generic `WebSocketTransport<Req, Resp>` (ee/tabby-webserver/src/axum/websocket.rs:36-127) wraps any WS stream/sink into a typed `Stream<Item = Req> + Sink<Resp>` with serde at the boundary, so per-endpoint setup collapses to a few lines - worth adopting as the typed boundary even under the Rustpad loop, but do not copy its `unwrap()` on inbound frame deserialization, which lets a malformed client kill the task. Spacedrive's session registry (`Connection { id, response_tx, filters }` in a `RwLock<HashMap>`, one central broadcaster task filtering per connection) is the shape to grow into only if we ever need server-side per-session filtering; today we do not.

### Finding 2: RAII cleanup and Drop-guard cancellation

Three codebases independently route lifecycle through Drop rather than manual cleanup calls. Trailbase's `AutoCleanupEventStream` (crates/core/src/records/subscribe/state.rs:45-111) pin-projects the event receiver and deregisters the subscription in `Drop` when the client disconnects, so no handler anywhere contains cleanup code. OpenObserve's `SearchStreamGuard` (api/search/src/search/utils.rs:156-217) moves into the response stream and cancels the backend query on Drop unless a terminal event marked the work finished - the exact shape for cancelling a gateway completion or a whisper job when the workshop client vanishes mid-stream. Rustpad's entry-Drop cascade is Finding 1's version of the same principle.

Application: wrap our per-connection resources (gateway stream, voice engine lease, tape span) in guards whose Drop releases them. This composes with Finding 1: when the connection task's single loop exits for any reason, everything owned by the task releases without a cleanup call site. Confidence: high.

### Finding 3: router decomposition - one constructor per feature, thin composition root

Tabby, Windmill, and Trailbase converge on the same decomposition. Each feature module exports a router constructor (`fn routes(state) -> Router`); the composition root is a short file that nests or merges them. Tabby narrows state per route group (`.with_state(ctx.job())`), so handlers depend only on the service they use, backed by a `ServiceLocator` trait with one `Arc<dyn Service>` getter per service (ee/tabby-schema/src/schema/mod.rs:102-126). Trailbase adds the discipline of directory-equals-domain, file-equals-endpoint, with the handler's request/response types and tests colocated in the endpoint file and `mod.rs` containing nothing but the route list (records/mod.rs:35-73). OpenObserve factors the serving shell itself into `server_addr()`, `apply_common_middlewares()`, and `serve()` (server.rs:52-120).

Application to `app.rs`: split into `routes/chat.rs`, `routes/voice.rs`, `routes/workspace.rs`, `routes/assets.rs`, each exporting `routes(state)`, with `app.rs` reduced to composition plus `AppState`. Adopt per-route state narrowing where a group uses one service. Two cautions from the same sources: Tabby's `ServerContext::new` grew to 18 positional parameters (group constructor inputs into structs early), and both Windmill (jobs.rs, 11,715 lines, inside a crate split that was supposed to prevent it) and Trailbase (list_records.rs, 1,507 lines) prove that neither crate boundaries nor file-per-endpoint save you from god files without active policing. Confidence: high.

### Finding 4: the feature-gated embed, and the embeddable-server API (gateway merge)

Windmill is the direct prior art for our planned merge of the workshop into the gateway binary. The whole `static_frontend` feature is one optional dependency (`static_frontend = ["dep:rust-embed"]`) plus a single `#[cfg]` on the body of the leaf serving function; the handler symbol and the `.fallback(static_handler)` registration compile unconditionally (windmill-api/src/static_assets.rs:92-141, lib.rs:1126). Headless and UI-serving builds have identical route trees, and no cfg appears in composition code. Their serving policy is also right: `/api/` misses return 404 rather than the SPA index, hashed assets get immutable caching, HTML gets no-store. The `#[folder = "${FRONTEND_BUILD_DIR:-../../frontend/build/}"]` env-with-default trick in the RustEmbed attribute is load-bearing in their Docker build and worth knowing.

Trailbase shows the embeddable-API shape from the library side: `Server::init(options)` and `serve()` split so the host composes before listening, a `custom_router: Option<Router<AppState>>` for host routes, and a documented `FromRef<CustomState>` pattern so the library's extractors work under the host's state (server/mod.rs:52-95, examples/custom-binary). It also shows the three embedding footguns to avoid, all of which it commits: `std::process::exit(1)` inside the listen path, unconditional global tracing init (its own comment admits this breaks the framework use case), and a rate-limiter `OnceLock` that ignores its argument after first call. Our merged-build plan already routes bind failures through the spawn handshake instead; keep it that way. Trailbase's optional separate-port admin router (server/mod.rs:165-196) is the same two-listener shape our merge plan chose. Confidence: high.

### Finding 5: shutdown - the force-exit watchdog and the triple handshake

Spacedrive and Trailbase both independently added a second-signal watchdog because held SSE/WS connections block axum's graceful shutdown indefinitely: first Ctrl-C starts graceful shutdown, a detached watchdog force-exits on a second signal or a 5-10s timeout (apps/server/src/main.rs:613-665; server/mod.rs:608-646). Our WebSockets give us the same exposure the moment a client wedges. OpenObserve upgrades the spawn contract itself to a triple handshake - init-success gate, shutdown signal, stopped barrier, then thread join (main.rs:160-254) - which is our bind-readiness mpsc plus oneshot, plus a stopped barrier we lack. Windmill's killpill broadcast with a phase-two channel that holds HTTP shutdown until workers drain is the same idea at monolith scale. Application: add the watchdog (roughly 40 lines) and the stopped barrier to `serve.rs`; the merged gateway inherits both. Confidence: high.

### Finding 6: two error types, not one and not three

Trailbase splits errors by boundary, with the rationale written in source: the wire error is "deliberately opaque and kept very close to HTTP error codes," bans thiserror's `#[from]` so every mapping is explicit, and leaks internal messages only in debug builds (records/error.rs:6-25, 96-99); the init error is a separate rich enum that uses `#[from]` liberally because it never crosses the wire (init_error.rs). Windmill shows the serviceable one-enum alternative with a central `IntoResponse` and a `Generic(StatusCode, String)` escape hatch. The failure modes bracket it from both sides: Tabby has no REST error type at all and hand-builds the same unauthorized response in three places, while Spacedrive has three coexisting error philosophies whose `From` impls flatten everything to `Internal(String)`. Application: our `AppError` should become the opaque wire error with explicit conversions; config and spawn errors stay rich. Confidence: high.

### Finding 7: asset serving refinements

Small, cheap upgrades from four sources. Cache immutable only what is content-hashed: Tabby applies `max-age=604800` solely to hashed `_next/` assets (routes/ui.rs:35-37), Trailbase's one-liner is justified in a comment by vite's hashed filenames, Spacedrive comments the invariant on the header. Exclude API paths from the SPA fallback so API 404s never return index.html (Windmill static_assets.rs:92-141; Tabby achieves it structurally by keeping a separate `(api, ui)` router pair merged only at the end, routes/mod.rs:14-28). Make the missing-bundle 404 diagnostic: Spacedrive's fallback tells you exactly which build command to run (main.rs:91-119). Trailbase's generic `AssetService<E: RustEmbed>` parameterized by a fallback closure (crates/assets/src/assets.rs:16-108) is the tidiest packaging if we touch this code anyway. OpenObserve's leaf embed crate - the UI embed isolated in a 305-line crate with zero config dependency so the ~50MB embed does not re-run through LLVM on unrelated changes - matters at their asset size, not yet at ours; note it for when the UI grows. Confidence: high on the header/fallback fixes, medium on restructuring around AssetService.

Decision (2026-08-27): the caching half of this finding is not adopted. The workshop UI is a windowed SPA served from the local process; nothing is cacheable, we set no cache headers, and the esbuild output keeps plain unhashed filenames - content hashes in filenames buy nothing here and are rejected. The SPA-fallback half does not apply either: `assets.rs` registers explicit per-file routes with no catch-all, so API misses already return 404. Only the diagnostic missing-bundle 404 remains relevant, recorded rather than scheduled.

### Finding 8: reconnect races and the push-transport spectrum

Spacedrive's event replay buffer kills the subscribe race we have on status-bar reconnect: the server retains 5 seconds or 100 events, and Subscribe does snapshot, register live, replay, in that documented order (infra/daemon/event_buffer.rs:21-57, rpc.rs:452-475), while the client attaches its listener before invoking subscribe. Separately, the field's transport choices calibrate ours: OpenObserve abandoned WebSockets entirely for live search in favor of HTTP/2 SSE with reconnect delegated to HTTP retry, and Windmill has zero inbound WS endpoints - all streaming is SSE. Full-duplex voice genuinely needs WS; the chat relay arguably does not, but our WS investment is made and bidirectional, so the actionable lesson is only the replay buffer plus Trailbase's `try_send`-on-bounded-channels rule so a slow client drops events rather than blocking siblings (state.rs:404-426). Trailbase's in-band WS auth (wait up to 10s post-upgrade for an `Init { auth_token }` message, close with code 1008 on failure, because browsers cannot set upgrade headers) is the pattern to file for when the workshop needs real auth. Confidence: high on the replay buffer, medium on the rest.

### Finding 9: test harness patterns

Every disciplined reference tests the server in-process, never against a spawned binary. Rustpad's entire harness is a 44-line `JsonSocket` wrapper over warp's test WS client plus route-level request helpers (tests/common/mod.rs, read first-hand), with real multi-client WS integration tests riding on it. OpenObserve rewrote its whole suite to `Router::oneshot` during the axum migration. Windmill's `ApiServer` fixture spawns `run_server` and awaits the port oneshot - our spawn contract already makes this trivial. Trailbase exports its `test_state()` builder from the library under `#[cfg(debug_assertions)]` so integration tests reuse the same construction as unit tests (lib.rs:14-15). Spacedrive's event-collector harness asserts on collected event streams instead of sleeping. Application: a small `tests/common` with a JSON-typed WS client and a spawn fixture would let us test both sockets without the current duplication. Confidence: high.

## The authorship signal

This study doubled as a natural experiment in AI-authored server code, and the correlation was stark. The two cleanest codebases are single-human-authored: Rustpad (0 of 88 commits AI-marked) achieves its five-file elegance by subtraction, and Trailbase (0 of 100, one author) maintains directory discipline across 68K lines. The two heavily AI-authored codebases exhibit the same disease in the same organs: Windmill (80 of 100 commits Claude co-authored) has an 11,715-line jobs.rs sitting inside the very crate split meant to prevent it, and Spacedrive (42 of 100 minimum) carries 4,660 lines of dead `watcher_old/` code, duplicated event filters with "keep in sync" comments, two competing connection-management schemes in one file, and `#![allow(warnings)]` on a 161K-line crate. Yet the same AI-authored codebases also contain unusually well-commented mechanisms (Spacedrive's replay-ordering rationale, its diagnostic 404s) - generation quality is fine; pruning and consolidation are what atrophy. The implication for us is the one the UI report already drew: enforce the structural rules mechanically (module size ratchets like OpenObserve's clippy line-count ratchet, layer lints, per-step review), because our code is AI-authored too and goodwill does not prune.

## Where we already match or beat the references

Our spawn/bind-handshake contract equals Windmill's and enables their best test pattern for free. Our graceful shutdown exceeds Tabby (which has none) and needs only the watchdog and stopped-barrier upgrades. Our typed `AppState` is what OpenObserve's own migration could not retrofit. Our config loader's `${ENV_VAR}` interpolation with precise errors is ahead of Tabby's inconsistent loader and simpler than Trailbase's protobuf reflection. Our disk-in-debug, embed-in-release asset scheme is the field standard. Keep all five.

## Human and AI messes we should explicitly not copy

Tabby: `unwrap()` on inbound WS frames, the 2,066-line auth.rs, 18-argument constructors, no graceful shutdown, ordering-as-security in route registration. OpenObserve: zero state injection (all global statics), the 875-line flat route-registration function, a 5,687-line config god-crate, the same audit block copy-pasted into every handler. Windmill: Extension-based DI that turns a missing dependency into a runtime 500, lazy_static env-read globals, 30-plus inline cfg-else pairs in one router expression, an 844-line `run_server`. Spacedrive: `Arc<RwLock<Option<Arc<T>>>>` late-bound DI (our `VoiceSlot` is one Option away from this; prefer phased construction), a 393-line god constructor where every failure logs-and-continues so the core boots silently degraded, races patched with sleeps, 99 operation directories of four-file ceremony. Trailbase: `process::exit` in a library listen path, unconditional global tracing init, singletons that ignore their arguments.

## Recommended execution order

1. Rewrite both WS handlers onto the Rustpad loop (Notify-plus-cursor durable path for chat transcript, bounded broadcast for status and interims), with Tabby's typed transport at the boundary and Drop-guard cleanup (Findings 1, 2). This deletes the duplication instead of abstracting it.
2. Split `app.rs` into per-feature `routes/` constructors with a thin composition root and narrowed state (Finding 3); do it together with step 1 since the same files move.
3. Shutdown hardening: force-exit watchdog plus stopped barrier in `serve.rs` (Finding 5). Small, independent, protects the merged gateway.
4. Error split: opaque wire error with explicit conversions, rich init error (Finding 6), naturally falling out of the step 2 file moves.
5. Dropped (2026-08-27): asset polish. No cache headers and no content-hashed filenames - the windowed SPA served from the local process caches nothing; API misses already 404 because the routes are explicit per-file with no SPA fallback. The diagnostic missing-bundle message is recorded, not scheduled (Finding 7).
6. Status-bus replay buffer and try_send discipline (Finding 8) when next touching reconnect.
7. Test harness: JsonSocket-style typed WS client and spawn fixture in `tests/common` (Finding 9), before step 1 if possible so the rewrite lands on a net.

For the merged gateway build, the plan already in flight should absorb Finding 4 directly: gate the leaf, keep composition feature-blind, keep bind failures in the spawn handshake, and keep the second listener.

## Refactor notes

The step 1 rewrite is a behavior change wearing a refactor costume: the wire protocol stays identical, but delivery semantics shift (ephemeral messages may drop under lag by design, durable messages coalesce). Write the two-semantics contract down in the protocol module before rewriting, and let the existing integration tests plus the new WS harness gate it. Steps 2-4 are pure structure with tests unchanged (step 5 was dropped: no caching, no content-hashed filenames). The existing suite stays green and intact throughout; per-step verify and commit per the vibe rulebook; if a step's tests fail twice, stop and re-plan.

## Actionable advice for the coming refactor

Standing directives for the plan that wraps this report. Everything here derives from the findings above; each directive names its source.

**1. Build the net before the rewrite.** The first commit of the refactor is the test harness (Finding 9): a typed JSON WS client over an in-process spawn fixture, in `tests/common`, plus characterization tests that pin the current chat and voice wire behavior end to end. Rustpad's 44-line harness proves this is a day of work, not a project. No session code moves until these tests exist and pass against the code as it is today. Confidence: high - the WS rewrite changes delivery semantics, and semantics changes without a net are how refactors turn into rewrites.

**2. Write the delivery contract before the code.** Before touching `chat_ws.rs` or `voice.rs`, add a short section to the protocol module stating which messages are durable (delivered exactly, coalesced, via Notify plus cursor) and which are ephemeral (droppable under lag, fully resent on reconnect, via bounded broadcast). Every message type gets classified. The Rustpad model only works when this line is explicit; classifying messages during the rewrite instead of before it is how the two semantics blur. Confidence: high.

**3. Delete, do not relocate.** The success metric for the session rewrite is negative diff in the session layer: the outbox channels, writer tasks, and session id plumbing disappear rather than moving into a shared module. If the refactor produces a new `ws_common.rs` that both handlers import for scaffolding, it has reproduced the disease one directory up - that is Spacedrive's duplication metastasized across crates, observed in a codebase 42 percent AI co-authored. What is allowed to be shared: the typed transport boundary (Tabby's shape) and the Drop guards (Finding 2). What stays per-feature: the inbound message match and the wire types. Confidence: high.

**4. One task owns the socket; everything it holds is a guard.** Per connection: one task, one `select!` loop, reads and writes on the same socket handle, no writer task. Every resource the task acquires (gateway stream, voice engine lease, tape span, registry entry) is wrapped so Drop releases it, and the loop's exit paths need no cleanup calls. If any resource still requires a manual cleanup call after the rewrite, the factoring is wrong. Confidence: high - three references converge on this and the fourth's manual cleanup is where its bugs live.

**5. Never `unwrap` on anything a client sent.** Malformed inbound frames get logged and skipped or close the connection with a policy code; they never panic the task. Tabby ships this bug today (`unwrap` on every inbound frame deserialization); Rustpad's `handle_message` shows the correct shape, returning early on non-text and wrapping deserialization in a context error. Enforce with the existing workspace clippy `unwrap_used` deny and no new allows in session code. Confidence: high.

**6. Split `app.rs` in the same series as the session rewrite, and impose the size ratchet at the same time.** The same files move for both, so moving them once is cheaper (this repeats the UI report's merge-the-moves lesson). When the `routes/` split lands, record the line count of every server module and add a check that fails verify when a module grows past its recorded ceiling plus slack - OpenObserve's ratchet, adopted because the field shows structure without enforcement regresses: Windmill's god files survived a crate split, Trailbase's survived file-per-endpoint. Our code is AI-authored; the ratchet is not optional. Confidence: high.

**7. Keep `AppState` typed and construction phased.** No service locator traits, no per-service `Arc<dyn>` getters, no registry macros - Tabby's ceremony pays at thirty services, not seven. Narrow state per route group with plain `with_state` where a group uses one service. And when the voice engine's late initialization tempts an `Arc<RwLock<Option<...>>>`, refuse: phase the construction instead. Spacedrive shows exactly where the settable-slot road ends (defensive re-registration, races patched with sleeps). Confidence: high on refusing the slot pattern, medium on how far to narrow state - stop when a handler's signature stops shrinking.

**8. Errors split by boundary, mappings explicit.** The refactor's error work is mechanical once stated: `AppError` becomes the opaque wire error, every variant maps to one status code, no `#[from]` across the wire boundary, internals leak only in debug builds; config and spawn errors stay rich and convenient. Do this as part of the `routes/` split, not as a separate pass, because the conversions live at the seams being cut anyway. Confidence: high.

**9. Shutdown hardening is independent - land it first if the big steps stall.** The force-exit watchdog and the stopped barrier touch only `serve.rs`, protect the merged gateway immediately, and need about 40 lines. There is no ordering dependency on anything else in this report. Confidence: high.

**10. Scope guard against this report itself.** The findings not in the execution order are recorded, not scheduled: the leaf embed crate waits until UI size hurts build times, the replay buffer waits for the next reconnect touch, in-band WS auth waits for a real browser-auth requirement, SSE-instead-of-WS is calibration rather than a migration. A refactor plan that absorbs every good idea it read is Spacedrive's 99-directory ceremony by another road. The plan implements Findings 1-3, 5, 6, and 9; it cites the rest. Confidence: high.

**11. Per-step done criterion, unchanged from the vibe rulebook.** Each step ends with the full verify green, the characterization tests unchanged (step 1 excepted, where the contract from directive 2 governs which assertions may change and why), and a commit. Two consecutive failures on one step stops the run for a re-plan. The suite is the invariant; it gets restructured last or never, not while the session layer is open. Confidence: high.
